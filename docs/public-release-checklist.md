# Public release checklist

## Source boundary

- [ ] Build the repository from a curated clean tree, not a provisioning directory.
- [ ] Rotate any credential previously pasted into chat, logs, scripts, or terminals.
- [ ] Scan the worktree and full Git history with at least two secret scanners.
- [ ] Confirm no real IPs, SSIDs, hostnames, keys, tunnel URLs/tokens, logs, or captures.
- [ ] Confirm screenshots were generated by the synthetic provider.
- [ ] Confirm no placeholder owner/repository links or deployment-specific URLs remain.
- [ ] Validate every Markdown and workflow link.

## Quality and security

- [ ] Unit, parser-contract, controller, layout, and render tests pass.
- [ ] armhf and arm64 hardware smoke tests pass on supported Raspberry Pi OS images.
- [ ] Ruff lint/format, mypy, ShellCheck, dependency audit, CodeQL, and workflow lint pass.
- [ ] Third-party GitHub Actions are pinned to reviewed commit SHAs.
- [ ] Threat model and security contact are current.
- [ ] Destructive controls pass bounce, double-tap, hold, cancellation, and timeout tests.

## Packaging and release

- [ ] Install, upgrade, rollback, and uninstall are idempotent.
- [ ] The service account is locked and distinct from all SSH users.
- [ ] Package contents, dependencies, license, and attribution have been reviewed.
- [ ] Version and changelog agree; release tag is signed.
- [ ] Artifacts include checksums and provenance attestations.
- [ ] Repository security advisories, secret scanning/push protection, branch
  protection, and required CI checks are enabled before accepting contributions.
